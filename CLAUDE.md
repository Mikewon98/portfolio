# CLAUDE.md

Guide to this repo for people and AI assistants. `AGENTS.md` is generated by `next dev` (Next.js agent rules). Leave it alone.

## What this is

Personal portfolio + blog for **michaelyze.com**.

- **Next.js 16** (App Router, React 19, Tailwind v4), built with `output: "standalone"`
- **Payload CMS 3** runs *inside* the same Next.js app. The admin UI is at `/admin` and the REST API at `/api/*`
- **Postgres 17** stores the data; uploaded images go to the `media/` folder (a Docker volume in production)
- Contact form email goes through **Resend**
- Deployed as a Docker image: GitHub Actions → GHCR → Watchtower on a VPS behind Traefik

## First-time local setup

1. `cp .env.example .env` and fill in the values. For local dev, `DATABASE_URI=postgres://payload:payload@127.0.0.1:5432/payload` works with `docker-compose.dev.yml`. Generate `PAYLOAD_SECRET` with `openssl rand -hex 32`.
2. `docker compose -f docker-compose.dev.yml up -d`
3. `npm install`, then `npm run dev`
4. Open http://localhost:3000/admin. The first visit asks you to create your admin account.
5. Optional: `npm run seed` imports the "VPS Setup and Initial Configuration" post.

In dev, Payload pushes schema changes straight to the local DB (`push: true` when `NODE_ENV !== "production"`).

## Writing a blog post

1. Go to `/admin` → **Blogs** → **Create New**.
2. Fill in:
   - **Title** (unique)
   - **Summary** (max 255 chars, shown on cards and as the meta description)
   - **Content**: rich text. Type `/` or use the toolbar for headings, lists, quotes, links and images. To add a code snippet, insert the **Code** block and pick a language. It renders with a copy button.
   - Sidebar: **Slug** (leave empty to generate from the title), **Date**, **Is Featured** (shows on the home page)
   - **Thumbnail** (card image) and **Featured Image** (post banner). Both are optional: cards show a green/purple gradient with the title, and the post page has no banner without them. Upload images in place; alt text is required.
3. **Save Draft** keeps it private. **Publish** makes it live straight away, because the pages are server-rendered on each request.
4. To unpublish, use **Unpublish** in the document menu. Drafts and unpublished posts never appear on the site, in the sitemap, or in the public `/api/blogs`.

## Changing the blog schema

1. Edit `collections/Blogs.ts` (or another collection).
2. `npm run generate:types`, then update pages if fields changed.
3. `npm run migrate:create -- describe-change` and commit the new file in `migrations/`.
4. Deploy. The production container runs pending migrations on start (`prodMigrations` in `payload.config.ts`).

## Environment variables

| Var | Where | Notes |
|---|---|---|
| `PAYLOAD_SECRET` | `.env` (local + server) | Long random string. Changing it logs everyone out |
| `DATABASE_URI` | `.env` (local) | In production, `docker-compose.yml` overrides it to point at the `postgres` service |
| `POSTGRES_PASSWORD` | `.env` (server) | Used by the `postgres` service and to build `DATABASE_URI` |
| `RESEND_API_KEY` | `.env` | Contact form |
| `DISCORD_WEBHOOK_URL` | `.env` (server) | Watchtower deploy notifications |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | optional | Let `npm run seed` create the first admin |

The Docker build needs **no** build args. The Dockerfile passes placeholder `PAYLOAD_SECRET` and `DATABASE_URI` values only for `next build`; real values come in at runtime. Never commit `.env` (it's gitignored; `.env.example` is the template).

## Deployment

1. Push to `main`. `.github/workflows/docker-publish.yml` builds and pushes `ghcr.io/mikewon98/blog:stable`.
2. Watchtower on the VPS polls every 300s, pulls the new image, and does a rolling restart of the `blog` service.
3. On boot, the app runs pending Payload migrations against the `postgres` service.

**One-time server steps for the Payload migration:**

- Add `PAYLOAD_SECRET` and `POSTGRES_PASSWORD` to the server's `.env`, and remove `NEXT_PUBLIC_STRAPI_URL`.
- Copy the new `docker-compose.yml` to the server and run `docker compose up -d`. This creates the `postgres` service and the `pgdata` and `media` volumes.
- Visit `https://michaelyze.com/admin` and create your admin user.
- Load the post: either recreate it in the admin, or run the seed against production once from your machine through an SSH tunnel (`ssh -L 5433:<postgres-container-ip>:5432 ...`, then `DATABASE_URI=postgres://payload:<pw>@127.0.0.1:5433/payload npm run seed`). Note that `docker-compose.yml` publishes no Postgres port.

**Backups**

- Database: `docker compose exec postgres pg_dump -U payload payload > backup.sql`
- Images: back up the `media` volume (e.g. `docker run --rm -v portfolio_media:/m -v $PWD:/b alpine tar czf /b/media.tgz -C /m .`). The volume name depends on the compose project name; check with `docker volume ls`.

## How blog data flows

`app/service/blogService.ts` calls `getPayload({ config })` and queries the `blogs` collection with `_status = published`, `depth: 1` (populates images), sorted by `-date`. Errors are caught and return `[]`/`null`, so a DB outage shows "No blog posts" instead of crashing. The home page, blog pages and sitemap use `dynamic = "force-dynamic"`. Each request reads the DB (a few ms), so new posts show up immediately and the build never needs the database. The `afterChange` hook in `collections/Blogs.ts` also calls `revalidatePath`, which matters if you ever switch those pages back to static/ISR.

Rich text is rendered by `app/components/BlogRichText.tsx` (`@payloadcms/richtext-lexical/react`) with custom converters: the Code block (reuses `CopyDiv`) and inline images. Body styling is the `.blog-content` block in `app/(frontend)/globals.css`.

## Migration log: Strapi → Payload (2026-11-20)

**Why:** Strapi Cloud moved to a paid plan and the hosted instance (`*.strapiapp.com`) and its data were removed. The site was showing no blog posts.

**Content recovery:** The old Strapi repo (`github.com/Mikewon98/blog`) held only the Strapi project. It had the `blog` schema, and `data/data.json` was Strapi's *demo* seed (coffee/pizza articles), so there were no real posts to import. The Wayback Machine had no snapshot of `/blog`. The one surviving post, "VPS Setup and Initial Configuration", came from a local text copy. It was rewritten in `seed/vps-setup.md` to match this repo's real setup: the Next.js standalone Dockerfile, GitHub Actions + GHCR, Traefik v3.6 with apex + www and sticky sessions, the `nickfedor/watchtower` fork with Discord notifications, and the Payload + Postgres section. The old Go "guestbook" and replicas parts were dropped. Sensitive data was replaced with placeholders: the ACME email, server IP, Linux username, webhook URL and tokens.

**Schema mapping (Strapi `blog` → Payload `blogs`):**

| Strapi | Payload | Change |
|---|---|---|
| `Title` (string, unique) | `title` | lower-case |
| `slug` (string) | `slug` | now unique + auto-generated from title |
| `date` (date) | `date` | — |
| `Summary` (text ≤255) | `summary` | — |
| `isFeatured` (bool) | `isFeatured` | — |
| `Thumbnail` (media, required) | `thumbnail` → `media` | now optional (gradient fallback) |
| `FeaturedImage` (media, required) | `featuredImage` → `media` | now optional |
| `Content` (Strapi Blocks) | `content` (Lexical rich text + Code block) | new format |
| draftAndPublish | `versions.drafts` | — |

- Traefik runs with `--api.insecure=true` and `--log.level=DEBUG`. The dashboard port isn't published, but consider removing both.
- `.env` holds `GITHUB_TOKEN`, and `env_file: .env` passes it into the app container, which doesn't need it.
